Cache anatomy: tag, index, offset

A cache answers three questions: which set should contain the block, whether the desired block is present, and where the requested byte sits inside that block.

What is a cache made of?

A simplified cache contains data storage, a tag for each line, valid/dirty state bits, selection logic, and control logic for misses. Real designs may add parity/ECC, replacement metadata, prefetching, banking and coherence state.

Break an address into fields

Tag
which memory block?|Index / set
where to look?|Offset
which byte?
  • Offset: selects a byte or word inside the cache line.
  • Index: selects a cache set (in a direct-mapped cache, effectively the only candidate line).
  • Tag: distinguishes which memory block is currently stored in that set.

Worked example

Suppose a toy cache has 256 bytes of data, 16-byte lines and 4-way associativity. It has 256 / 16 = 16 lines total. At 4 lines per set, it has 4 sets. The offset needs log2(16) = 4 bits. The index needs log2(4) = 2 bits. The remaining upper address bits are the tag.

For byte address 0x1234, offset is the lowest 4 bits: 0x4. The set index is the next 2 bits. The tag is everything above them. In actual RTL, address width, physical/virtual tagging and implementation details matter.

Mapping options

DesignWhere a memory block can goTrade-off
Direct-mappedExactly one line/set locationSimple, low area and fast; conflict evictions can be frequent.
N-way set associativeAny of N ways within one indexed setFewer conflicts, but more tag comparisons and replacement state.
Fully associativeAny line in the cacheFlexible placement, but searching and replacement are more expensive.

What happens on a hit?

  1. Use address bits to select the set.
  2. Compare requested tag with valid tags in the candidate way(s).
  3. If a valid tag matches, the access is a hit.
  4. Use offset bits to select requested bytes/word.

What happens on a miss?

A miss means the requested block is not currently available in that cache in a usable state. The controller selects a victim if necessary, obtains the block from a lower level, installs its tag/data, updates metadata and completes the access. If a dirty victim is evicted from a write-back cache, it may need to be written back first.

Replacement and metadata

Replacement policy chooses a victim line in a set. LRU means least recently used; pseudo-LRU approximates it with less state; random chooses a candidate randomly. A valid bit says whether the line contains meaningful cached data. A dirty bit says the cached data differs from backing memory under a write-back policy.

Associativity: number of alternative line slots (“ways”) available for a block within its set. A 4-way cache has four candidate lines per set, not four cache levels.
