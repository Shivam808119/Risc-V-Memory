RISC-V MEMORY LAB

Memory errors, protection, MMIO and DMA

A memory system must do more than return bytes quickly. It must reject illegal accesses, report failures, preserve device semantics, and sometimes detect corrupted data.

Protection

Protection mechanisms limit which software or hardware agents can access which address ranges. Depending on the system, this can involve privilege modes, page permissions, PMP regions, bus firewalls, an IOMMU for devices, or access-control logic around a peripheral.

Integrity: parity and ECC

Parity adds a check bit that can detect some bit errors but usually cannot correct them. Error-correcting code (ECC) adds redundancy to detect and sometimes correct corruption. Exact capabilities depend on code and implementation. A core may carry integrity bits on an interface without implementing the RAM's ECC itself.

Access faults and response errors

A bus target may report that an address is unmapped, a transfer timed out, or a device detected an error. The interconnect may propagate an error response; the core may convert it to an exception or trap. A robust integration needs a defined response for every address range, including unmapped regions.

MMIO vs normal RAM

Memory-mapped I/O exposes device registers at addresses. Reading a register may acknowledge an interrupt or pop a FIFO; writing a register may start hardware. Caching, speculation, reordering or merging transactions can break device behavior unless the region is correctly marked and accessed according to the platform rules.

DMA and IOMMU

DMA (direct memory access) lets a device transfer data without the CPU copying every byte. On a non-coherent system, CPU caches may not automatically notice DMA writes or may contain stale data. Software may need to clean/invalidate cache lines with the platform's prescribed sequence. An IOMMU translates/restricts device DMA addresses, similar in purpose to CPU virtual-memory translation but for device accesses.

Questions for any real SoC

  • What happens on unmapped address accesses?
  • Are instruction and data memories protected differently?
  • Are caches coherent with DMA, or is software maintenance required?
  • Are ECC/parity bits generated and checked in the core, cache, SRAM macro or controller?
  • Can a request time out? Can a bus error become a precise CPU exception?
  • Are MMIO regions marked non-cacheable and appropriately ordered?
