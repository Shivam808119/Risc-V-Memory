How to investigate memory in RTL

Turn concepts into evidence: trace a request from the core port to the target, and document exactly which logic is present in the configuration you are studying.

A repeatable RTL workflow

  1. Pin down the design. Record repository URL, branch/tag/commit, parameters, generated config and SoC/board.
  2. Find the top module. Identify instruction fetch, load/store, reset and clock ports.
  3. Trace request signals. Search for names such as mem_valid, mem_ready, instr_req, data_req, req, gnt, rvalid.
  4. Follow the connection. Does the port connect directly to SRAM, a cache, a bus adapter, a crossbar or a larger interconnect?
  5. Find state. Search for arrays, tag RAM, valid/dirty bits, refill state machines, miss-status registers, queues and TLB structures.
  6. Read parameters. Determine if optional features are enabled in the configuration you will actually build.
  7. Confirm with tests. Look for tests of load/store, misalignment, bus stalls, faults, cache refill/eviction, fences and atomics.

What terms in RTL often mean

FSMFinite-state machine: control states and transitions for a multi-cycle operation such as a cache refill.
HandshakeSignals that define when a transfer is accepted or completed.
FIFOFirst-in, first-out queue. Used to buffer requests/data while producer and consumer run at different rates.
MSHRMiss-status holding register: tracks an outstanding cache miss and its refill; used in nonblocking caches.
VictimThe cache line selected for replacement when a set needs room.
RefillFetching a cache line from a lower memory level after a miss.
Flush / invalidateOperations to write back dirty data and/or mark cached copies unusable; exact meaning depends on operation.
BackpressureThe receiver cannot accept more work, so the sender must wait or hold its request stable.

Questions to answer in your notes

  1. Does instruction fetch use a dedicated interface?
  2. Can data loads and stores be outstanding simultaneously?
  3. How are byte and halfword accesses handled?
  4. Where are access faults signaled?
  5. Is there a cache? What are line size, capacity, ways, replacement and write policy?
  6. Is there a TLB/MMU? Which privilege modes are implemented?
  7. What handles atomics, fences, DMA and cache maintenance?
  8. Which properties are core RTL and which are added by the SoC?
Do not infer a cache from the word “prefetch”. A prefetch FIFO can hold fetched instructions without being a general-purpose instruction cache. Likewise, a bus buffer is not necessarily a cache, and a TLB stores translations rather than data.
