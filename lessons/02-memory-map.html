Memory system: the big picture

Memory is not one box. It is a set of addressable resources and mechanisms that move instructions and data between a core, nearby storage, larger memory and devices.

What does “memory” mean?

In computer architecture, memory is any storage the processor can access through an address: instruction ROM/flash, SRAM, DRAM, cache arrays, control/status registers in devices, and sometimes memory-mapped peripherals. The word memory system includes the storage plus the logic and protocols that make accesses work.

Instruction path and data path

PC (next instruction address)→Instruction fetch→Decode / execute

Separately, for a load/store instruction:

Registers + immediate→Effective address→Load/store unit↔Data system

PC means program counter: the address of an instruction being fetched. A load reads data from an address into a register. A store writes register data to an address. Instruction fetch and data access are conceptually different even when a design shares a physical bus.

Address space and memory map

An address is a number used to identify a location or target. A memory map assigns ranges of addresses to resources. Example only: low addresses could select boot ROM, another range SRAM, a range external DRAM, and a high range UART or GPIO registers. Real addresses come from the board/SoC manual.

ROM / flashStores boot code or program image persistentlyRead/write behavior and speed depend on technology/controller.

CacheKeeps copies of blocks to reduce average access timeCorrectness requires a policy for fills, writes and sharing.

How a load actually travels

  1. Decode identifies a load instruction and its base register plus offset.
  2. The address-generation unit calculates the effective address.
  3. The load/store unit checks access size, alignment, permissions and ordering rules as applicable.
  4. The request enters the selected interface. It may hit a cache or go to an interconnect/memory controller.
  5. The target accepts the request, finds/reads the data and returns a response.
  6. The core selects the requested byte/halfword/word, sign-extends or zero-extends where required, then writes the result to a register.
Effective address: the address calculated by the instruction, often base-register value + immediate offset. It is not necessarily the physical RAM location; virtual-memory systems may translate it.

Latency versus bandwidth

Latency is how long one request takes to produce a usable result. Bandwidth is how much data can be transferred per unit time after transfers are flowing. A road analogy: latency is how long one car takes to reach a destination; bandwidth is how many cars pass per hour. A system can have high bandwidth and still have high latency for a single dependent load.

Why the memory system affects performance

  • A core cannot use a load result until the needed data arrives, unless the microarchitecture can do other independent work meanwhile.
  • Instruction fetch stalls can starve the pipeline even if arithmetic hardware is fast.
  • Many small random accesses stress latency; streaming large arrays stress bandwidth.
  • Extra buffers and queues can overlap requests, but consume area and need more complex control.

Terms in this lesson

Backing memoryThe lower-level storage used when a faster level does not contain the requested block.
Memory controllerLogic that schedules and performs transactions to a memory technology such as DRAM.
Master / initiatorA component that starts a transaction, such as a CPU or DMA engine.
Target / subordinateA component that receives and responds to transactions, such as SRAM or a peripheral.
ThroughputAmount of useful work/data completed per unit time.
StallA period when progress must wait for a condition such as a response or available resource.
