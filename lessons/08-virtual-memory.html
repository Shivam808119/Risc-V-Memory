RISC-V MEMORY LAB

Virtual memory, page tables and TLBs

Virtual memory translates the addresses used by software into physical addresses and enforces access permissions. The TLB is a small cache of translation results—not a cache of ordinary data bytes.

Virtual vs physical address

A virtual address (VA) is the address software uses in a virtual-memory environment. A physical address (PA) identifies a location in the system's physical address space. The memory management unit (MMU) performs translation and permission checks. Some small embedded cores do not implement a full virtual-memory MMU; check the exact design.

Virtual address→TLB lookup→Physical address→Cache / interconnect / memory

If the translation is absent, hardware/software may perform a page-table walk or raise a fault, depending on architecture and mode.

Pages and page tables

Virtual memory divides addresses into fixed-size pages. A page table maps a virtual page number to a physical page number plus permissions and status bits. The offset within the page is usually unchanged by translation. Multi-level page tables reduce the amount of contiguous memory needed for sparse address spaces.

What does the TLB do?

TLB stands for translation lookaside buffer. It caches recent VA→PA mappings and permission information. On a TLB hit, translation is fast. On a TLB miss, the system must find the mapping—often by walking page tables—or report a translation fault. A TLB miss is not the same as an L1 data-cache miss: one concerns address translation; the other concerns data availability.

Permissions and faults

Mappings can encode whether a page is readable, writable, executable, user-accessible, supervisor-only, or otherwise restricted. A load from a forbidden page, store to a read-only page, or instruction fetch from a non-executable page can fault. Exact rules depend on the RISC-V privileged architecture version and implemented privilege modes.

Translation changes and stale entries

When software changes page tables, a processor may have cached old translations. RISC-V uses the SFENCE.VMA instruction in relevant supervisor-mode contexts to order page-table updates with address-translation activity. It is not a universal “clear every cache” instruction. Multiprocessor systems may need coordination so other harts stop using stale translations.

Cache and TLB interactions

Cache indexing/tagging may use virtual or physical address bits. A physically tagged cache usually checks physical identity; a virtually indexed physically tagged (VIPT) cache uses virtual bits for a fast set lookup and physical address for tag identity. Aliasing synonyms and homonyms can complicate virtually addressed caches. These are implementation-level details, not requirements of every core.

Page fault / access faultAn exception indicating translation, permission, or physical access failed; exact exception categories differ.
Page-table walkHardware or software reads page-table entries to find a mapping.
ASIDAddress-space identifier used to distinguish translations from different address spaces where supported.
MMUHardware for translation and protection; not every core has one.
