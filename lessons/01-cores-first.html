First, meet the ten cores

A core is a hardware implementation of the RISC-V ISA. These designs differ in area, throughput, configurability and the system around them. Understand the design target before comparing memory features.

What is a CPU core?

A CPU core is the hardware that fetches instructions, decodes them, performs operations and updates architectural state. The ISA (instruction-set architecture) is the contract visible to software: instruction encodings, registers, exceptions and memory-operation behavior. The microarchitecture is how the implementation achieves that contract.

Program / instructions→CPU core↔Memory system↔RAM / ROM / devices

A SoC (system-on-chip) is the larger system: core(s), memories, interconnect, timers, interrupt controllers, DMA engines, and peripherals. A core can have a memory interface without containing the RAM itself.

Ten core families at a glance

CoreWhat to rememberMemory study focus
SERVBit-serial, area-focused RV32 coreMemory-system learning angle: extremely small core with serial execution; inspect its exact external memory/bus wrapper rather than assuming a cache.
PicoRV32Compact configurable RV32 coreIts native memory port is a simple valid/ready transaction interface. It does not imply a cache; the SoC designer supplies memories, bridges, and peripherals.
IbexSmall in-order RV32 core from lowRISCSeparate instruction-fetch and load/store paths; request/grant and response-valid concepts; optional instruction cache/integrity features depend on configuration and integration.
VEGAA family of RISC-V processor implementationsDo not treat VEGA as one single configuration. Identify the exact model/RTL, system platform, memory map, cache and interconnect documentation first.
CV32E40P4-stage in-order 32-bit CORE-V processorOfficial docs describe OBI-compliant instruction-fetch and load/store data interfaces. Its prefetch machinery must not automatically be called a conventional cache.
Rocket CoreConfigurable in-order RISC-V core in Rocket ChipGenerated systems often use TileLink and configurable cache/TLB structures. Values belong to a particular generated configuration, not every Rocket instance.
SweRV EH1Dual-issue, in-order RISC-V core from the SweRV familyStudy the exact release documentation and RTL for LSU, load/store ordering, cache assumptions, bus adapter and integration-level memory system.
VexRiscvPlugin-configurable FPGA-friendly RV32 coreMemory capabilities depend on selected plugins: simple/cached instruction and data buses, translation, and bridge choices are not universal defaults.
SonicBOOMConfigurable out-of-order RISC-V core familyMemory study focuses on load/store queue, speculation, dependency checks, replay, cache/TLB configuration and the surrounding Rocket Chip/Chipyard system.
ShaktiIndian RISC-V processor family, multiple classesClass matters: different Shakti designs target different applications and may have different pipelines, cache/MMU and integration choices. Verify the exact class and version.

Why these ten are useful comparisons

Minimalism

SERV helps show how a tiny serial datapath changes performance expectations. Small hardware often relies on simple external memory arrangements.

Simple integration

PicoRV32 makes request/ready handshakes easy to observe. You can see that the memory controller or fabric is outside the core.

Embedded efficiency

Ibex and CV32E40P are useful for learning fetch and load/store interfaces, latency, grants, and response-valid signals.

Configuration

Rocket, VexRiscv, VEGA and Shakti require you to identify the exact variant or generated configuration.

More performance machinery

SweRV EH1 and especially SonicBOOM/BOOM motivate studying multiple outstanding operations, queues, speculation and cache interaction.

Five distinctions you must keep straight

  1. ISA vs core: the ISA defines software-visible behavior; a core is one hardware implementation.
  2. Core vs SoC: the core issues requests; the SoC decides where addresses go and connects actual memory/peripherals.
  3. Cache vs RAM: a cache is a small, fast copy of recently useful memory blocks; RAM is a backing store.
  4. Interface vs protocol: an interface is the signals/ports; a protocol defines when signals are asserted and how transactions complete.
  5. Optional vs present: a configurable core can support a cache/MMU without every build containing one.

Terminology checkpoint

RTLRegister-transfer level: hardware described in Verilog/SystemVerilog or another HDL.
PipelineStages that overlap work from different instructions.
In-orderInstructions are issued/completed according to a constrained program order.
Out-of-order (OoO)Independent operations may execute when ready even if older operations are waiting, while architectural behavior is preserved.
Parameter / configurationA compile-time choice that changes which hardware is generated.
Interconnect / fabricThe on-chip network connecting masters (requesters) to memory/peripherals.

How to research one core correctly

  1. Find the official repository and user manual.
  2. Record the exact core name, release/tag/commit and board/SoC integration.
  3. Find top-level instruction and data interface ports.
  4. Trace where those ports connect: SRAM, cache, bus adapter, crossbar, TileLink/AXI/OBI, or a custom fabric.
  5. Find parameters that enable caches, MMU/TLB, PMP, integrity, ECC or extra outstanding requests.
  6. Confirm with RTL and tests. A README summary is a starting point, not proof for every generated design.
