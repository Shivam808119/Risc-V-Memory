CORE PROFILE

SonicBOOM memory system profile

Configurable out-of-order RISC-V core family. Memory study focuses on load/store queue, speculation, dependency checks, replay, cache/TLB configuration and the surrounding Rocket Chip/Chipyard system.

How to read this profile: verified general characteristics are separated from questions you must confirm for your exact build. Core-family capability is not proof that your configuration enables a feature.

What it is

SonicBOOM, commonly called BOOM in documentation, is a configurable out-of-order RISC-V core family built in the Rocket Chip/Chipyard ecosystem. Compared with small in-order cores, memory analysis must include speculative execution, queues and dependencies as well as caches.

Why an OoO core needs more memory machinery

An out-of-order core may execute a younger independent instruction while an older load is waiting. To preserve correct program behavior, it must track operations, detect dependencies, avoid exposing incorrect speculative state, and handle replay or recovery when an assumption proves wrong.

Load/store queue concepts

A load queue tracks loads that have been issued but not fully retired. A store queue tracks stores and can check whether a younger load overlaps an older store. Store-to-load forwarding may provide data from an older store. If the core discovers that a load used stale data because an older store's address was not yet known, it may need to replay work or recover according to the implementation.

Cache/TLB configuration

BOOM's memory behavior is coupled to generated Rocket Chip parameters and the surrounding memory hierarchy. Identify the exact configuration's I-cache, D-cache, TLB, interconnect and coherence options. Do not infer cache capacity or associativity from “BOOM” alone.

What to inspect

  1. Load/store unit and load/store queue design documentation.
  2. Cache/TLB parameters in the generated configuration.
  3. How memory dependence is checked and what causes replay.
  4. How exceptions and speculative loads are handled.
  5. Interconnect response ordering, outstanding transaction limits and coherence protocol.

Key performance concept: MLP

BOOM can potentially have multiple memory requests in flight, increasing memory-level parallelism (MLP). However, queue entries, miss-status structures, cache ports, TLB misses and DRAM bandwidth are finite. A dependent pointer chase may still serialize despite out-of-order execution.
