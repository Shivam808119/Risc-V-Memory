CORE PROFILE

PicoRV32 memory system profile

Compact configurable RV32 core. Its native memory port is a simple valid/ready transaction interface. It does not imply a cache; the SoC designer supplies memories, bridges, and peripherals.

How to read this profile: verified general characteristics are separated from questions you must confirm for your exact build. Core-family capability is not proof that your configuration enables a feature.

What it is

PicoRV32 is a compact configurable RV32 core designed to be easy to integrate, including in FPGA/ASIC systems. Its native memory interface is a useful beginner example because the transaction contract is visible in a small set of signals.

Native memory interface

SignalMeaning
mem_validThe core is presenting a memory transfer.
mem_readyThe peer acknowledges/completes the transfer according to the native interface timing.
mem_addrAddress for the transfer.
mem_wdataWrite data.
mem_wstrbByte-lane write enables; zero indicates a read, nonzero indicates a write.
mem_rdataRead data supplied by the peer.
mem_instrIndicates an instruction fetch transaction on the shared native interface.

The request remains asserted until the peer is ready, and the core's outputs remain stable during the request. Consult the official README for the exact contract. The optional look-ahead interface announces aspects of the next transfer earlier, which can help timing in some integrations but may make timing closure harder because some signals are combinational.

What is outside the core?

The memory interface does not mean PicoRV32 includes a general cache or DRAM controller. The SoC builder maps addresses to block RAM, external memory, ROM, MMIO, or a bridge. AXI4-Lite and Wishbone variants/wrappers can be used depending on the configuration and integration.

How to study it

  1. Find the interface declarations and the state machine that asserts mem_valid.
  2. Follow mem_addr into the top-level SoC address decoder.
  3. Inspect the memory implementation and whether it responds in the same cycle or after wait states.
  4. Test byte writes by inspecting mem_wstrb.
  5. Compare native interface behavior with any selected bus wrapper.

Performance questions

How many cycles does a load take when ready is immediate? How many when the target waits? Can the core have multiple native data transfers outstanding? What does the look-ahead path change? The documented native interface handles one transfer at a time, so do not attribute OoO-style memory-level parallelism to it.
