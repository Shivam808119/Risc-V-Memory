CORE COMPARISON

Compare memory systems across ten RISC-V cores

A guided comparison focused on memory—not a ranking of cores. Use the profile pages to verify each design’s exact interfaces, cache options, translation and SoC integration.

How to compare fairly

First identify the exact model and configuration. A configurable core may have multiple possible memory systems. This table is a research starting point, not a claim that every feature is enabled in every build.

Don't compare only by cache size

One core may have no cache but use low-latency on-chip SRAM; another may have a cache but connect to a slow target. A high-performance core may overlap misses but also contend for bandwidth. Compare the whole path: access latency, throughput, queue depth, cache behavior, address translation, coherence and target memory.

Evidence standard

  1. Prefer official manuals for intended behavior.
  2. Use RTL to confirm the implemented signal/control path.
  3. Use the actual generated configuration to determine enabled features.
  4. Use tests/simulations to validate observed behavior.
  5. Record uncertainties explicitly.
