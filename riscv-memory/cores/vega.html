CORE PROFILE

VEGA memory system profile

A family of RISC-V processor implementations. Do not treat VEGA as one single configuration. Identify the exact model/RTL, system platform, memory map, cache and interconnect documentation first.

How to read this profile: verified general characteristics are separated from questions you must confirm for your exact build. Core-family capability is not proof that your configuration enables a feature.

First identify the exact VEGA design

VEGA refers to a family/project rather than one universal fixed microarchitecture. Different processor models and system platforms can differ in pipeline, cache/MMU choices, memory ports and interconnect. Before making claims, record the exact core name, release, configuration and SoC.

How to investigate its memory system

  1. Start with the official project and the documentation for the exact model.
  2. Locate the top module and find instruction-fetch and load/store interfaces.
  3. Search for cache, TLB/MMU, SRAM, bus adapter and interconnect modules in that model.
  4. Inspect the memory map and integration example: core ports alone do not reveal which address ranges map to RAM or devices.
  5. Check if the implementation is intended for a microcontroller, embedded Linux or another target; that affects expected memory hierarchy.

Questions that must be answered from the chosen version

  • Are instruction and data ports separate?
  • Is there an L1 instruction or data cache? If yes, what are line size, associativity, capacity and write policy?
  • Is there an MMU/TLB or only physical addressing/protection?
  • What bus protocol connects the core to the memory system?
  • How are stalls, errors and unaligned accesses represented?
Evidence rule: Do not copy a cache feature from one VEGA model onto another. Mark a feature “not verified” until the exact model manual, RTL/configuration or integration proves it.

How to write a reliable report

Use a table with columns: feature, present in exact build?, evidence path, configuration parameter, notes. If a public document does not answer the question, state that the source did not establish it rather than filling the gap with a guess.

Official sources to begin with

  • Documentation / project source — use this to locate the matching manual, RTL and release notes.
  • Repository — inspect the actual implementation and configuration.
