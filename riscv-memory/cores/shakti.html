Shakti memory system profile

Indian RISC-V processor family, multiple classes. Class matters: different Shakti designs target different applications and may have different pipelines, cache/MMU and integration choices. Verify the exact class and version.

How to read this profile: verified general characteristics are separated from questions you must confirm for your exact build. Core-family capability is not proof that your configuration enables a feature.

What it is

Shakti is an Indian RISC-V processor initiative with multiple core classes and implementations. The class and version are essential: a microcontroller-oriented core and an application-class core should not be assumed to share a memory hierarchy.

How to identify the correct memory architecture

  1. Choose the exact Shakti class/model and repository revision.
  2. Find its architecture/user manual and top-level RTL.
  3. Determine the implemented ISA and privilege features.
  4. Trace instruction and data access interfaces and the connected interconnect.
  5. Check for caches, TLB/MMU, PMP, atomics and coherence in that particular design.
  6. Read the SoC memory map and identify the real memory/peripheral targets.

Why the family distinction matters

Processor families can share an ISA while differing in pipeline, cache capacity, MMU, bus protocol and intended workload. The ISA alone does not answer whether virtual memory exists, whether caches are coherent, or whether an L2 cache is present.
