CORE PROFILE

VexRiscv memory system profile

Plugin-configurable FPGA-friendly RV32 core. Memory capabilities depend on selected plugins: simple/cached instruction and data buses, translation, and bridge choices are not universal defaults.

How to read this profile: verified general characteristics are separated from questions you must confirm for your exact build. Core-family capability is not proof that your configuration enables a feature.

What it is

VexRiscv is a configurable FPGA-friendly RISC-V core built using SpinalHDL. It is assembled from plugins, so the memory subsystem depends on which plugins and parameters are selected.

Simple and cached buses

The project documents simple instruction/data plugins and cached instruction/data plugins. A simple bus is a direct command/response-style interface. A cached plugin adds cache behavior such as line lookup and refill. Do not assume the cached plugins are present just because the core family supports them.

Translation and MMIO mapping

VexRiscv configurations can include memory-translation plugins, including an MMU/TLB arrangement, and static address-region logic that marks I/O as uncached. This is configuration-specific. The address translator and cache plugin must cooperate correctly so device accesses are not accidentally treated like ordinary cached RAM.

How to read its plugin list

  1. Find the Scala configuration that instantiates the core.
  2. Identify whether it uses IBusSimplePlugin or IBusCachedPlugin.
  3. Identify whether it uses DBusSimplePlugin or DBusCachedPlugin.
  4. Check the memory translator/MMU plugin and address regions.
  5. Trace bridges to AXI4, Avalon or Wishbone, if present.

Why plugin architecture matters

Plugin-based hardware lets one project generate small or more feature-rich designs. The source repository describes capabilities, but your instantiated plugin list is the actual design contract. Two VexRiscv bitstreams can have different cache, MMU, pipeline and bus behavior.

Terms

PluginA hardware-building block inserted into a generated configuration.
IBus / DBusInstruction bus and data bus.
MMU pluginOptional logic for virtual-to-physical translation.
Uncached regionAddress range bypassing a cache to preserve device semantics or avoid stale data.
