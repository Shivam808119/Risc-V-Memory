SweRV EH1 memory system profile

Dual-issue, in-order RISC-V core from the SweRV family. Study the exact release documentation and RTL for LSU, load/store ordering, cache assumptions, bus adapter and integration-level memory system.

How to read this profile: verified general characteristics are separated from questions you must confirm for your exact build. Core-family capability is not proof that your configuration enables a feature.

What it is

SweRV EH1 is a dual-issue, in-order RISC-V core in the SweRV family. Dual issue means it can issue more than one instruction in a cycle under suitable conditions; it does not mean all memory operations can complete in one cycle or that the core is out-of-order.

Memory topics to investigate

For EH1, rely on the exact release's user guide and RTL for the LSU, instruction/data access paths, cache assumptions, bus interfaces and supported outstanding transactions. Avoid importing details from another SweRV variant or from a third-party SoC wrapper.

Why dual issue changes the questions

More instruction issue bandwidth can expose memory bottlenecks: if both issue slots are ready but a load is waiting, dependencies or LSU resource limits may prevent useful progress. The core's scheduling and in-order rules constrain which instructions can pass a blocked memory operation.

Study checklist

  • Find the load/store pipeline and request-generation logic.
  • Find instruction-fetch and data-memory interface specifications.
  • Determine whether caches are inside the core or expected externally for the exact design.
  • Record ordering rules, misaligned access handling, errors and fences.
  • Inspect how stalls/backpressure affect issue and pipeline progress.

Performance questions

What is the hit/miss path in the chosen system? Can the core have multiple requests pending? How do load-use dependencies stall the pipeline? Does the interface allow response reordering? Which buffering is in the core and which is in the bus/SoC? Answer from the relevant guide and RTL, not from the phrase “dual issue.”
