Cache misses, the three Cs and AMAT

Cache performance depends on how often accesses miss and how costly each miss is. AMAT is a useful first model, but it is not a full performance simulator.

The three classic miss categories

Compulsory miss

The first access to a block misses because it has not yet been brought into the cache. Also called a cold miss.

Capacity miss

The useful working set exceeds what the cache can retain, so previously used blocks are evicted and needed again.

Conflict miss

Blocks compete for the same set even though other sets or lines may be unused. More associativity can sometimes help.

Average Memory Access Time (AMAT)

For a simple one-level cache model:

AMAT = hit time + miss rate × miss penalty

Use consistent units. Example: hit time in cycles, miss rate as a fraction, miss penalty in cycles.

Worked example: L1 hit time = 1 cycle, miss rate = 5% = 0.05, miss penalty = 40 cycles.
AMAT = 1 + 0.05 × 40 = 3 cycles per memory access in this simplified model.

This does not mean every load takes exactly 3 cycles. Some take 1 cycle and some take many more. AMAT is an average under the assumed workload and model.

Multiple levels

For L1 and L2, one common model is:

AMAT = L1 hit time + L1 miss rate × (L2 hit time + L2 miss rate × L2 miss penalty)

Be careful about whether an L2 miss rate is local (misses divided by L2 accesses) or global (misses divided by all CPU accesses). Mixing them gives a wrong result.

Latency and overlap

AMAT is most straightforward when accesses are treated as a serial sequence. Out-of-order cores can overlap independent misses; prefetchers may fetch data before the program asks; memory-level parallelism allows multiple outstanding requests. In such systems, wall-clock execution time is not simply “number of loads × AMAT.” Dependencies, queue capacity, bandwidth and contention matter.

How to improve performance?

  • Reduce hit time—but larger/more associative caches can make lookup slower.
  • Reduce miss rate using better capacity, associativity, replacement or prefetching.
  • Reduce miss penalty with lower-level caches, better memory scheduling, or a faster memory system.
  • Overlap misses using nonblocking caches, queues and out-of-order execution, when supported.
  • Improve locality in software where possible.
Memory-level parallelism (MLP): how many memory operations can be in progress at once. A core with MLP can hide some latency, but it still consumes bandwidth and finite queue entries.
