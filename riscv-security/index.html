Security is a system property

A processor can implement useful security mechanisms, but the product is only as strong as the complete chain: boot, privilege, memory protection, interconnect, debug, firmware, keys, and verification.

How to use this guide

  1. Read Start here: the ten cores.
  2. Study lessons 02–12 in order. Every lesson defines important terms and explains why they matter.
  3. Choose a core and inspect its profile. Begin with PicoRV32 for a straightforward interface or Ibex to study explicit security-oriented features.
  4. Record exact evidence. Mark every finding as verified, inferred, or unknown.
  5. Turn each claim into a test: allowed accesses should succeed, forbidden accesses should fail without side effects.
Critical distinction: RISC-V is an ISA standard, not one CPU design. A feature may be optional, configuration-dependent, implemented in the SoC rather than the core, or absent. Never claim that a core has PMP, an MMU, secure boot, authenticated debug or side-channel resistance without evidence for the exact build.

Security topics covered

Resilience

Bus integrity, ECC/parity, alert paths, fault injection, debug security and secure failure.

Verification

Threat models, negative tests, assertions, source tracing, reproducible evidence and residual risk.
