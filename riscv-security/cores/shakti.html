Shakti security profile

Security review guide for Shakti: what the core is, which threat boundaries to investigate, and how to verify claims in the exact implementation.

What this profile can and cannot say: Shakti contains multiple core classes with different goals and feature sets. Identify the exact class, implementation revision and SoC. Then inspect privilege modes, PMP/MMU, debug lifecycle, boot ROM, bus fabric, peripheral protection and any security documentation. Family-level descriptions are not enough to establish a concrete security guarantee. This page is a research plan, not a certification or a claim that every listed security mechanism is present.

What is this core?

Family of RISC-V processor cores. A core implements an ISA and microarchitecture; the surrounding SoC determines much of the real security posture. Keep those layers separate while researching.

What security should you investigate in Shakti

Identify the class and implementation

Shakti is a family. Record the class, release, privilege support and system integration; different classes should not be treated as one fixed design.

Privilege and memory protection

Verify actual PMP/MMU and privilege implementation, region configuration and fault behavior. Check whether hardware enforcement applies to all CPU accesses.

Debug, boot and peripherals

Inspect debug lifecycle, immutable boot stage, firmware authentication, reset behavior, bus-master access and peripheral isolation.

Evidence-based conclusions

For every feature, cite exact source/configuration and test it. If no source proves a capability, mark it 'unknown' rather than 'supported'.

Checklist: gather evidence

  • Exact repository, release tag or commit hash.
  • Top-level module and all security-relevant configuration parameters.
  • Supported privilege modes and CSR access checks.
  • Physical memory protection and/or virtual-memory translation, if any.
  • Instruction-fetch and load/store fault paths; whether denied operations have side effects.
  • Debug authentication, test interfaces, reset defaults and lifecycle behavior.
  • Bus/interconnect protection for every master, including DMA and accelerators.
  • Secure boot, firmware update and key provisioning in the complete platform.
  • Side-channel, integrity, fault-detection and alert behavior, with limits documented.
