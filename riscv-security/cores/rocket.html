CORE PROFILE

Rocket Core security profile

Security review guide for Rocket Core: what the core is, which threat boundaries to investigate, and how to verify claims in the exact implementation.

What this profile can and cannot say: Rocket is normally configured and integrated through the Rocket Chip ecosystem. Privilege support, page translation, PMP, caches and coherence behavior must be checked in the generated configuration and SoC. Security review must include TileLink/interconnect protection and peripherals, not just the CPU pipeline. This page is a research plan, not a certification or a claim that every listed security mechanism is present.

What is this core?

Configurable in-order RISC-V core generator. A core implements an ISA and microarchitecture; the surrounding SoC determines much of the real security posture. Keep those layers separate while researching.

What security should you investigate in Rocket Core

Generated configuration is the product

Rocket is parameterized and usually integrated via Rocket Chip. Inspect the generated core configuration, tile parameters, address map and SoC topology.

Privilege and virtual memory

Confirm M/S/U support, page-table translation, PMP entries, delegation, trap handling and relevant CSR controls in the selected configuration.

Coherence and shared state

Review cache hierarchy, coherence topology and which cores/devices share caches. Shared microarchitectural state may create side-channel concerns even when architectural permissions are correct.

TileLink and peripherals

Trace access-control enforcement across TileLink and all masters. CPU PMP is not a universal replacement for device DMA isolation, peripheral firewalls or debug lifecycle controls.

Checklist: gather evidence

  • Exact repository, release tag or commit hash.
  • Top-level module and all security-relevant configuration parameters.
  • Supported privilege modes and CSR access checks.
  • Physical memory protection and/or virtual-memory translation, if any.
  • Instruction-fetch and load/store fault paths; whether denied operations have side effects.
  • Debug authentication, test interfaces, reset defaults and lifecycle behavior.
  • Bus/interconnect protection for every master, including DMA and accelerators.
  • Secure boot, firmware update and key provisioning in the complete platform.
  • Side-channel, integrity, fault-detection and alert behavior, with limits documented.
