PMP, Smepmp and physical access control

PMP is one of the most important hardware mechanisms to understand when auditing embedded RISC-V systems.

What PMP does

Physical Memory Protection provides per-hart configuration registers that describe physical address regions and allowed read, write and execute access. For accesses covered by PMP rules, hardware can reject disallowed operations. PMP is optional; inspect the implementation and its number/granularity of entries.

Why physical matters

PMP checks physical addresses after translation decisions, so it complements virtual memory rather than replacing it. A system with no MMU can still use PMP for region-based isolation if the core and platform implement it.

NAPOT and TOR

PMP address matching modes include naturally aligned power-of-two regions (NAPOT) and top-of-range (TOR) regions. These encodings have alignment and boundary details. Learn the exact specification before hand-writing entries; off-by-one and priority mistakes can leave gaps.

Locking

Locked entries can prevent later software changes until reset, with specific architectural rules. Locking can protect boot code or immutable regions. It is not enough to set a lock bit without verifying entry priority, reset behavior and all masters that can access the target.

Smepmp

The ratified Smepmp extension strengthens PMP behavior, including options that can restrict M-mode access to regions allocated to lower-privilege software. It addresses important privilege-escalation patterns. Support is optional and must be confirmed.

PMP is not a complete SoC firewall

Standard PMP is per hart and governs that hart's relevant accesses. DMA engines and other bus masters may not pass through the CPU's PMP checks. Protect them with an interconnect firewall/IOMMU or equivalent system mechanism.
