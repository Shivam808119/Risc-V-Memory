Side channels, speculation and constant-time code

A program can leak information through behavior that is observable even when the architectural result is correct.

What is a side channel?

An attacker observes timing, power, electromagnetic emissions, cache behavior, branch behavior or other indirect signals to infer secrets. No direct read of the secret is required.

Constant-time programming

Avoid secret-dependent branches and memory accesses in cryptographic code when the threat model includes timing/cache observers. Use reviewed cryptographic libraries; source-level constant-time intent must be checked against compiler output and hardware behavior.

Data-independent timing

Some cores offer special controls or dummy-operation techniques to reduce input-dependent execution behavior. Such features have limits, must be enabled correctly and do not automatically remove every power or EM leakage path.

Speculative execution

An out-of-order core may execute instructions before all branches or memory checks are resolved. Some effects may remain in microarchitectural state after a misprediction. Analyze actual design and documented mitigations rather than assuming all RISC-V cores share one vulnerability profile.

Cache side channels

Shared caches can reveal access patterns. Consider partitioning, flushing, scheduling, constant-time algorithms, cache policies and system topology as appropriate. Flushing alone is not a universal fix.

What to record

Attacker observation, secret-dependent operation, observable signal, required co-residency, noise/repeatability, mitigation and residual risk.
