Interconnect, DMA, peripherals and I/O isolation

CPU privilege checks only protect transactions that actually pass through them.

Bus master

A bus master can initiate transactions without the CPU executing a load/store for each one. Examples include DMA engines, network interfaces, display engines and accelerators.

The DMA trap

If a DMA engine can read all physical RAM, an isolated user process may still lose secrets through a malicious or compromised device. CPU PMP may not be applied to that DMA transaction.

IOMMU or firewall

An IOMMU translates and restricts device DMA addresses; an interconnect firewall can restrict a master to specific regions. Confirm that every master and path is covered and that configuration cannot be changed by untrusted software.

MMIO

Memory-mapped I/O registers control devices. Access permissions, register side effects, reserved bits and ordering matter. Treat device control registers as privileged assets.

TOCTOU

Time-of-check to time-of-use occurs when a value is checked and later changes before use. DMA can make this especially dangerous: validate data into protected memory or use ownership/synchronization protocols.

Reset and ownership

When a peripheral is reassigned or reset, clear stale descriptors, pending interrupts and DMA permissions. Review isolation during boot, shutdown, suspend and error recovery.
