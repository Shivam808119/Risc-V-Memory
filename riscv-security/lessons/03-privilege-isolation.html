Privilege modes, traps and isolation

Understand how software privilege boundaries work in RISC-V and what they do not protect by themselves.

M, S and U modes

Machine mode (M) is the highest standard privilege level and is required by the base privileged architecture. Supervisor mode (S) commonly hosts an OS. User mode (U) is for applications. Implementations can support different subsets. Lower privilege is not a sandbox unless hardware checks enforce it.

Trap and return

Exceptions and interrupts transfer control to a configured trap handler. The handler must validate cause, origin and arguments, avoid leaking privileged data, and return using the appropriate instruction. A trap handler is security-critical code.

CSRs

Control and Status Registers hold architectural control state, privilege configuration, trap state and counters. Check which mode may access each CSR and whether custom CSRs introduce undocumented access paths.

Privilege escalation

An attacker attempts to gain higher privilege, e.g. by exploiting a bug in a supervisor service, misconfigured protection region or unsafe return path. Privilege modes reduce risk only when memory access and privileged operations are correctly constrained.

M-mode caution

M-mode has broad machine control. If untrusted software can execute in M-mode, conventional U/S isolation may be insufficient. PMP and extensions such as Smepmp can strengthen boundaries, but exact implementation and lock semantics must be verified.
