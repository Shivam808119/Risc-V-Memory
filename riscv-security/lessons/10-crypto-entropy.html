Cryptography, entropy and key handling

Cryptography is a system, not just an instruction extension or accelerator.

Cryptographic building blocks

Hash functions provide digests; MACs authenticate data using a shared key; signatures authenticate with public/private keys; encryption protects confidentiality; KDFs derive keys. Use standard, reviewed algorithms and protocols.

Entropy and TRNG

A true random-number generator samples physical entropy; a DRBG expands a seed into pseudorandom output. Security depends on entropy quality, startup health tests, reseeding, failure handling and correct software APIs.

Crypto instructions

ISA extensions can accelerate operations but do not automatically provide secure key storage, constant-time behavior for all operations or correct protocol use. Verify extension availability and software dispatch.

Side-channel resistant implementation

Consider timing, cache access, power, EM, fault attacks and compiler transformations. A mathematically correct algorithm can still leak keys in its implementation.

Key lifecycle

Provision, store, use, rotate, revoke and erase keys. Minimize copies and lifetime in ordinary RAM. Define behavior on debug, crash, reset, update and factory-reset paths.

Hardware accelerator boundary

If an accelerator has DMA or bus-master capability, verify its address permissions, command validation, key-slot access controls and isolation from unrelated memory.
