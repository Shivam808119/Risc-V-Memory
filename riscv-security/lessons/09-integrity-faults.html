Integrity, fault detection and error reporting

Security needs more than access control: the system should detect corruption and respond safely.

Data integrity

Integrity mechanisms detect accidental or malicious corruption. Parity detects some bit errors; ECC can detect/correct selected error patterns; cryptographic authentication protects against stronger adversaries. These mechanisms are not interchangeable.

Bus integrity

A core or interconnect can carry check bits alongside requests/data. A receiver checks that the value and check bits agree. Review coverage: instruction data, load data, addresses, control signals, responses and all relevant bus segments.

Error propagation

An error signal is only useful if it reaches a handler or security controller and causes the intended response. Trace it end-to-end and check whether corrupted load data can still update architectural state.

Fault containment

A failure in one domain should not corrupt another domain. Isolation may require bus error checking, timeouts, privilege protection, reset domains and independent monitoring.

Alerts

Differentiate recoverable events, suspicious events and fatal alerts. Check latching, clear policy, interrupt routing, logging and whether an attacker can flood or suppress the alert channel.

Do not overclaim

A bus-integrity feature does not automatically detect a malicious but internally consistent transaction, unauthorized access by another master, or every fault-injection attack.
