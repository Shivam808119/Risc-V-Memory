Security foundations and threat models

Learn the security vocabulary before studying specific hardware protections.

Confidentiality, integrity, availability

Confidentiality means unauthorized parties cannot learn secrets. Integrity means unauthorized parties cannot change code, data or control state unnoticed. Availability means the system continues to provide its required service. One mechanism rarely guarantees all three.

Asset, attacker, trust boundary

An asset is something valuable, such as a signing key, firmware image or sensor reading. An attacker is the entity with capabilities the design must resist. A trust boundary is where assumptions change—for example, between U-mode software and M-mode firmware, or between a CPU and a DMA-capable device.

Threat model

Write down attacker access, capabilities, goals, and out-of-scope cases. Can the attacker run arbitrary user code? Control a peripheral? Observe timing or power? Physically probe the board? Fault-inject the clock or voltage? Different answers require different protections.

Attack surface

Every input or privileged capability that can be abused: instruction decoder, CSR path, bus transaction, DMA engine, debug port, boot strap, firmware parser, update mechanism and test interface.

Security property vs mitigation

A property is the desired outcome ('user code cannot read secret SRAM'). A mitigation is a mechanism (PMP region, bus firewall, page-table permission, secure monitor). A mitigation only works if it is configured, connected to every relevant path, and verified.
