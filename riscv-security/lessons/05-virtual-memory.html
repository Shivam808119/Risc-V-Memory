Virtual memory, page tables and TLB security

Virtual memory provides address translation and page-level permissions, but creates its own correctness and side-channel questions.

Virtual vs physical address

A virtual address is what software uses under translation. The MMU maps it to a physical address and checks permissions. Physical addresses ultimately select RAM, ROM or device regions.

Page-table permissions

Page-table entries can encode read, write, execute, user/supervisor and other permissions. W^X means a region should not be writable and executable at the same time; enforcement and mapping policy must be checked.

TLB

A Translation Lookaside Buffer caches translations and permission information. It improves performance, but stale entries after page-table changes can cause correctness or isolation bugs if required invalidation and fences are missing.

Process isolation

An OS usually gives processes different virtual address spaces. Page tables separate them only if mappings and privilege transitions are correct, kernel memory is protected, and all DMA/device paths are considered.

Speculative and timing concerns

Even when an architectural access eventually faults, speculative execution or microarchitectural state may have observable effects in some designs. Page permissions alone do not prove resistance to all side channels.
